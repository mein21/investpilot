# Аудит и план: детерминированный скринер российских акций

Дата аудита: 2026-10-28. Источник контракта: локальный клон `investAPI`
(commit `3eaf23a25f598fe483c913184acdbd9132bc68d2`, release 1.43 от 2025-11-07)
и read-only проверки production API.

## 1. Что уже есть в проекте

`investpilot-local` — локальный портфельный менеджер на FastAPI, SQLAlchemy и
Jinja. Он умеет синхронизировать счёт, считать аллокацию, формировать
рекомендации и вести журнал. Для новой задачи это источник проверенного
T-Invest транспорта, но не готовая система отбора акций.

Существующий growth-модуль (`app/rules/growth.py`, `app/services/growth.py`)
нельзя использовать как основу нового рейтинга без исправлений:

- оборот считается как `close * volume`, без множителя `lot`; для GAZP,
  MTSS, AFLT и других бумаг с лотом больше 1 это занижает ликвидность;
- минимальная история — 63 наблюдения, а для 12-месячного моментума нужно
  не менее 252;
- при недостатке истории возвращается нейтральный 50, поэтому бумага с
  неполными данными может попасть в середину рейтинга;
- по умолчанию в выборку входят ETF, а не только обыкновенные и
  привилегированные акции;
- нет сравнения с бенчмарком, сектором, объёмным подтверждением, пробоем,
  риском, стаканом, дивидендами и корпоративными событиями;
- нет walk-forward, издержек, проверки достижения цели и статистической
  неопределённости;
- `INSTRUMENT_STATUS_BASE` создаёт survivorship bias: делистингованные
  бумаги не попадают в историческую проверку.

Вывод: growth-модуль остаётся как есть, новый скринер добавляется отдельным
пакетом `app/screener/` и не меняет торговый контур.

## 2. Матрица доступности данных T-Invest

| Бенчмарк IMOEX | `GetCandles` по `Indicatives` | Да | Ценовой индекс, без дивидендов; история длиннее | Резервный бенчмарк с оговоркой |

| Стакан | `MarketDataService/GetOrderBook` | Да, только текущий | Нет истории; после закрытия пустой; depth 1–50 | Текущий спред, только если стакан качественный |

| Расписание торгов | `InstrumentsService/TradingSchedules` | Да | Нельзя запрашивать дату раньше текущей | Календарь MOEX |

| Отчёты | `InstrumentsService/GetAssetReports` | Да | Даты публикации, без исторических значений | Метаданные и планирование обновления |
| Сплиты и корпоративные действия | Отдельного метода нет | Нет | Можно только обнаруживать аномальные гэпы | Флаг качества, без молчаливой корректировки |

Проверенные факты production API:

- `Shares` в `INSTRUMENT_STATUS_BASE`: 1912 инструментов; `Shares ALL` —
  8048. После фильтра MOEX + RUB + обыкновенные/привилегированные остаётся
  331 листинг, после дедупликации по `asset_uid` — 314, из них активных 252.
  Активных TQBR — 252; ещё 14 активных MTQR относятся к OTC-режиму
  (`exchange=otc_ncc`) и исключены. Если считать MTQR, получается 266.
  Foreign OTC-расписки (например, AAPL-RM) тоже имеют
  `REAL_EXCHANGE_MOEX` и RUB, поэтому фильтра по `real_exchange` недостаточно:
  нужен TQBR или явный MOEX trading mode.
- SBER имеет один основной листинг TQBR (lot=1); в `ALL` у него есть
  дополнительные листинги, поэтому выбирать первый элемент нельзя.
- MCFTR: 1482 дневных бара с 2020-12-01 по 2026-10-27. Диапазон загрузки
  свечей — 2150 календарных дней, чтобы после прогрева в 252 сессии можно
  было проверять сигналы с 2022 года.
- SBER: 1148 завершённых дневных свечей за 4 года; сегодняшняя свеча
  `isComplete=false` и должна отбрасываться.
- `GetOrderBook` после закрытия возвращает пустой стакан; фильтр спреда
  должен корректно работать при отсутствии данных.
- У SBER в фундаментале `ebitda`, `freeCashFlow`, `totalDebtToEbitda` равны
  0, а `netMargin` отсутствует; для финансового сектора это нормальная
  особенность, а не «нулевая» компания. Нули трактуются как `None`.
- `fiscalPeriodEndDate` может быть не заполнен; дата снимка — только
  `fetched_at`, поэтому PIT-бэктест фундаментала невозможен.

## 3. Ограничения, которые нельзя обойти

1. **Survivorship bias.** Даже `ALL` не гарантирует полный список когда-либо
   торговавшихся бумаг. Историческая проверка на текущем списке будет
   оптимистичнее реальности; это нужно писать в отчёте.
2. **Фундаментал не point-in-time.** `GetAssetFundamentals` — текущий снимок.
   Использовать его в историческом рейтинге нельзя без отдельного PIT-
   источника. В бэктесте — только техническая модель.
3. **Сплиты.** API не отдаёт историю сплитов. Резкие гэпы помечаются и
   исключаются из рейтинга, а не корректируются догадками.
4. **Стакан.** Истории нет. Текущий спред можно проверить только в момент
   запуска; для истории используется консервативная модель издержек.
5. **Дивиденды.** Для total return выплата добавляется на дату отсечки, не на
   дату объявления; в признаках цены до ex-date корректируются
   мультипликативно. Возможны пропуски и нестандартные выплаты.
6. **Малый горизонт проверки.** MCFTR доступен с 2020-12; после 252 сессий
   прогрева остаётся около 4 лет. Это даёт 18 когорт с шагом 63 сессии —
   мало для уверенных выводов, особенно с учётом перекрывающихся горизонтов.
7. **Старые корпоративные действия.** Проверка подозрительных гэпов
   ограничена последними `min_history_sessions` (252) сессиями: старый
   неучтённый сплит не должен блокировать текущий рейтинг, но он может
   искажать длинные ряды. Сплиты API не корректирует.

## 4. Архитектура

```
app/screener/
  domain.py      доменные записи: инструмент, бар, дивиденд, метрики, результат
  config.py      параметры вселенной, фильтров, рейтинга, издержек и бэктеста
  tinvest.py     read-only адаптер поверх TInvestRestClient
  store.py       SQLite: instruments, bars, dividends, fundamentals, runs
  quality.py     проверки истории, пропусков, нулевых объёмов, гэпов, сталей
  features.py    моментум, тренд, объём, пробой, риск, ликвидность
  market.py      режим рынка и широта
  rating.py      процентильная нормализация, A–E, штрафы, объяснения
  screen.py      загрузка, фильтры, ранжирование, результат
  backtest.py    walk-forward, издержки, альтернативы, bootstrap
  report.py      HTML/JSON/Markdown
```

Принципы:

- только чтение; ни одного вызова `PostOrder`, `CancelOrder` или sandbox-
  операций;
- `ScreenerTInvestClient` наследует `TInvestRestClient` и переиспользует
  `_read`/`_validated`, не меняя ABC и mock;
- отдельная SQLite-база `data/screener.db`, чтобы не трогать основную БД;
- деньги и доходности — `Decimal`, объёмы — целые лоты, время — UTC;
- отсутствие данных — `None` и флаг, никогда не 0 и не средний рейтинг;
- все результаты воспроизводимы по `as_of`, параметрам и версии данных.

## 5. Методика рейтинга

Все признаки считаются только по завершённым свечам до даты сигнала
включительно. Процентили считаются внутри текущей допустимой выборки.

| Блок | Вес | Что измеряет |
|---|---:|---|
| A. Относительная сила и моментум | 30% | доходность 3/6/12 мес. за вычетом MCFTR; 6 мес. без последних 5 сессий; ускорение; секторный относительный результат при ≥5 бумагах в секторе |
| B. Качество тренда | 20% | цена выше SMA20/50/200, наклон SMA200, доля дней выше SMA50, просадка от 52-недельного максимума; наклон SMA50 оставлен только в диагностике из-за ρ≈0.90 с устойчивостью |
| C. Подтверждение объёмом | 20% | рост оборота к базе, оборот на росте против падения, стабильность оборота |
| D. Консолидация и пробой | 20% | сжатие диапазона, близость к максимумам 63/126 сессий, комбинированный пробой 63/126 без текущей свечи, подтверждение оборотом |
| E. Умеренность риска | 10% | волатильность, ATR, максимальная просадка, частота крупных overnight-гэпов, бета |

Штрафы: аномальный 5-дневный ход, чрезмерное удаление от SMA50, нестабильный
оборот, чувствительность рейтинга к изменению весов на ±10%. Критические
флаги качества (нет истории, низкая активность, подозрительный гэп, битые
OHLC) исключают бумагу из рейтинга. Если часть блоков недоступна, рейтинг
считается по доступным весам с предупреждением; если недоступны все блоки,
кандидат исключается.

Фундаментал в режиме `technical_fundamental` используется как
дополнительный фильтр и отдельная колонка, но не подменяет A–E и не
участвует в историческом бэктесте. Режим требует минимум 2 доступных
критерия на бумагу; если покрытие допустимой выборки ниже 50%, список не
формируется и выводится предупреждение вместо тихого технического рейтинга.

## 6. Бэктест

- Сигнал — после закрытия сессии.
- Вход — открытие следующей торговой сессии с проскальзыванием.
- Горизонт — 63 сессии; выход — закрытие 63-й сессии.
- Цель +20% проверяется по максимуму внутри горизонта; превышение бенчмарка
  +10 п.п. считается по чистой доходности.
- Издержки: комиссия 0,3% на вход и выход, проскальзывание 15 б.п. на
  сторону, участие не более 5% дневного оборота (по умолчанию).
- Walk-forward: параметры выбираются только на прошлых когортах; обучающие
  когорты с фактическим выходом не раньше первого сигнала теста исключаются
  (purge/embargo). Следующая когорта — тест. Основные результаты — out-of-sample.
  Финальный holdout очищен тем же правилом.
- Альтернативы: бенчмарк, равновзвешенная вселенная, простой 6-месячный
  моментум, случайный отбор с теми же ограничениями, Top-5, Top-10,
  фиксированные параметры с рыночным фильтром и без него.
- Неопределённость: Wilson 95% ДИ для долей и блочный bootstrap по когортам
  для средних и частот; при малом числе наблюдений — `None` и предупреждение
  «Недостаточно данных», без подмены нулём.
- Чувствительность: несколько значений порога рейтинга и числа кандидатов;
  если результаты резко меняются, это фиксируется, а не скрывается.
- Диагностика: корреляции признаков, IC каждого признака и блока по когортам,
  ablation блоков, разбивка по режимам рынка.
- Издержки: комиссия и проскальзывание отдельно на входе и выходе, в сделке,
  в портфеле и как доля среднего капитала.

## 8. Запуск и первый фактический прогон

```bash
# Первый прогон: обновляет Shares, MCFTR, свечи TQBR и недостающие дивиденды.
.venv/bin/python -m app.cli screen --no-orderbook --top 5

# Повторный анализ только по кэшу, без сети.
.venv/bin/python -m app.cli screen --no-refresh --no-orderbook --top 5 \
  --html data/reports/screen.html --json data/reports/screen.json \
  --md data/reports/screen.md

# Walk-forward на кэше.
.venv/bin/python -m app.cli screen-backtest --no-refresh --start 2021-01-01 \
  --train 1 --step 63 --top 10
```

Первый полный прогон 2026-10-28 занял около 48 секунд на свечи и ещё
около 91 секунды на явное обновление дивидендов (`--refresh-dividends`).
Без флага дивиденды догружаются только для uid, по которым ещё нет
успешной записи в `fetch_log`, поэтому прерванный прогон можно продолжить.

## 9. Что не делаем

- не выставляем заявки и не включаем автоторговлю;
- не используем LLM/ML для прогноза;
- не обещаем доходность, вероятность или «гарантированные» кандидаты;
- не подбираем параметры на всей истории;
- не подменяем отсутствующие данные нулями или средними;
- не используем фундаментал в историческом бэктесте как PIT-данные.
